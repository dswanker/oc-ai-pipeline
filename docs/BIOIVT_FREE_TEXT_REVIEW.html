Built 2026-10-05 from the real Detroit and Precision specs (conventions applied). Read-only; nothing changed. Full table: docs/BIOIVT_FREE_TEXT_REVIEW.csv.

1. The Indication question (Concomitant Medications)

Yes, it can be a type-ahead list, and it's a small change.
  • What the standard says. CDASH collects Indication (CMINDC) as free text. CDISC publishes no code list for it. CDASHIG advises collecting it so the medication itself can be coded (the same drug can have different meanings by indication or route).
  • What can code it. A diagnosis vocabulary. SNOMED CT is the one we already have as a 7,137-term list, and it is the standard vocabulary for conditions in OMOP. MedDRA is what pharma usually uses, but it is licensed and we don't have it. ICD-10-CM is free if you prefer it.
  • What I'd build. Type-ahead over the SNOMED list with an Other (not in list), specify box, so what the site types is always kept next to the code (your coded-plus-verbatim rule). It is one convention for both studies, and the mechanism is the one already working on the diagnosis questions.
  • One caution. People often give a symptom ('pain', 'headache') as the indication. Our list is disease families, so some symptoms will fall to Other. I can add SNOMED clinical findings to the list if you want better coverage.

3. Rules I applied (your approved six)

  1. Nothing becomes untypeable: every coded question keeps an Other box.
  2. Coded plus verbatim: the typed words are kept next to the code.
  3. Values come from a standard where one exists; otherwise from what your sites actually enter, and you approve them.
  4. Numbers and times become proper types, not choice lists.
  5. No list goes live until you approve its values.
  6. Old data is matched separately.
